# FUTUREVIEW Personal — Engineering Rules

- Inspect the repository and relevant behavior before changing it.
- Preserve working behavior unless a change explicitly replaces it.
- Prefer no new dependency; add one only for a demonstrated need.
- Do not add speculative abstractions or unrelated refactors.
- Prefer deterministic simulation over AI magic.
- Keep UI, domain, navigation, simulation, and scenario concerns separate.
- Treat the occupancy-grid/A* code as a prototype to adapt, not a mandate for the final model.
- Test meaningful behavior, including paths, mutations, reproducibility, and scenario effects.
- Update context documentation when architecture or durable scope decisions change.
- Do not claim unsupported accuracy, accessibility compliance, safety guarantees, or real-world prediction.
- Repository reality overrides documentation assumptions; planned work is never implemented work.
- Keep the spatial scene primary and avoid dashboard-heavy product decisions.
